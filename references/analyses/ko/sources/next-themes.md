# 자료 분석: next-themes

## 편집 평가

### 범위 적합성

이 저장소는 시스템 선호, 저장된 선택, DOM 속성, hydration 문제, 선택적 transition 억제를 관리하는 React/Next.js 테마 라이브러리를 문서화한다. 플랫폼이 클라이언트 제어 테마를 구현한다면 직접 관련되며 단순해 보이는 토글 뒤의 예외를 보여준다.

### 권위와 지속 가능성

프로젝트 저장소는 API, 예제, 라이선스, 현재 동작의 1차 출처다. 라이브러리 세부는 버전 의존적이므로 채택 전에 다시 확인해야 한다. README는 패키지 사용에는 강하지만 일반 UX 주장 근거는 아니다.

### 중복 및 분류

제안 형식: `repository documentation`. 제안 Area: `frontend-engineering`, `theming`. `disable-transitions-temporarily`의 테마 동작을 구현 수준으로 확장한다.

### 편집 권고

`review`. 구현별 문서로 유지한다. freshness 날짜를 붙이고 모든 Next.js 테마에 이 의존성이 필요하다고 암시하지 않는다.

## 웹사이트 디자인 분석

### 정보 계층과 탐색

GitHub의 저장소 정체성과 탐색 안에서 README가 설치, 예제, API, 주의점 순으로 진행한다. 구현자에게 효율적이지만 플랫폼 크롬이 많다.

### UI, 인터랙션 및 모션

코드 복사, 탐색, 검색, issue, star, 저장소 액션이 있다. 인터랙션 상태와 모션은 실행하지 않았다.

### 그리드, 레이아웃 및 반응형 동작

저장소 탐색이 코드·표가 포함된 중앙 README 열을 둘러싼다. 좁은 화면은 테스트하지 않았다.

### 타이포그래피, 색상 및 시각적 리듬

제목, badge, 코드, 옵션 표, 경고가 기술 탐색을 돕는다. 정확한 대비와 테마 변형은 감사하지 않았다.

### 접근성 관찰

의미 있는 제목과 코드 블록이 구조를 제공한다. 복사 버튼, 포커스, 표, 모바일 탐색은 런타임 테스트가 필요하다. 잘못된 hydration으로 표시 상태가 로드 뒤 바뀌는 문제도 접근성에 영향을 준다.

### 전이 가능한 원칙

- 시스템 선호, 저장 선호, 해석된 테마를 구분한다.
- 서버·클라이언트 불일치가 잘못된 UI를 만들지 않게 한다.
- 안정된 문서 속성으로 테마 상태를 적용한다.
- transition 억제를 tradeoff가 있는 명시 옵션으로 둔다.
- 채택 시점에 의존성 문서를 다시 확인한다.

### 복제하지 않아야 할 출처 고유 표현

README 문장, 예제, badge, GitHub 레이아웃, 저장소 브랜딩, API 설계를 독립 결정 없이 복제하지 않는다.
