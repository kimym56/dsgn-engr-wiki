# 콘텐츠 전략

> 이 문서는 [`docs/content-strategy.md`](../content-strategy.md)의 한국어 번역본입니다. 영문 원본을 기준 문서로 사용합니다.

## 목적

콘텐츠 시스템은 방문자가 가치 있는 디자인 엔지니어링 자료를 발견하고, 원 출처로 이동하기 전에 각 자료가 왜 관련 있을 수 있는지 이해하도록 도와야 합니다.

편집 순서는 다음과 같습니다.

```text
발견 → 평가 → 원 출처 방문
```

프로젝트는 선정, 구성, 맥락을 더합니다. 참조하는 외부 작업을 대체하지 않습니다.

## 콘텐츠 객체

### 참고 자료 레코드

참고 자료 레코드에는 다음이 포함됩니다.

- 자료 제목과 기준 URL
- 게시자와, 유용한 경우 저자
- 프로젝트가 작성한 간결한 요약
- 자료가 디자인 엔지니어링에 중요한 이유에 대한 짧은 설명
- 자료 형식과 하나 이상의 분야
- 선택적 컬렉션 관계
- 원문 언어, 상태, 추가 날짜, 최근 실질적 검토 날짜
- 선택적 원 게시 날짜
- 승인된 미리보기 이미지 또는 프로젝트의 중립적 대체 이미지

### 분야

분야는 참고 자료 전반에 공유되는 안정적인 주제 분류입니다. 분야 페이지는 디자인 엔지니어링과의 연결을 간략히 설명하고, 별도의 콘텐츠 시스템에 요약을 복제하지 않고 일치하는 자료를 표시합니다.

### 컬렉션

컬렉션은 목적, 질문 또는 학습 결과를 중심으로 기존 참고 자료를 선별한 편집 셀렉션입니다. 선택이나 순서가 중요한 이유를 설명할 수 있지만 같은 기준 참고 자료 레코드를 가리킵니다.

### 편집 페이지

홈, 소개, 선정 정책, 컬렉션 소개 콘텐츠는 문서 구조가 유용할 때 Markdown 또는 MDX를 사용할 수 있습니다. 인터랙티브 MDX 컴포넌트는 기본 콘텐츠 형식이 아니라 예외로 유지해야 합니다.

## 참고 자료 메타데이터 모델

콘텐츠 시스템이 구현되면 모든 참고 자료는 다음 필드를 포함해야 합니다.

| 필드              | 목적                                                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------ |
| `id`              | 프로젝트가 소유하는 안정적인 식별자                                                              |
| `title`           | 게시된 자료 제목 또는 의미를 바꾸지 않고 편집상 정리한 제목                                      |
| `url`             | 기준 외부 목적지                                                                                 |
| `publisher`       | 자료를 책임지는 조직 또는 사이트                                                                 |
| `author`          | 확인 가능하고 유용한 경우 개인 저자                                                              |
| `summary`         | 카드와 검색에 사용하는 프로젝트 소유의 간결한 설명                                               |
| `relevance`       | 자료가 디자인 엔지니어링에 중요한 이유                                                           |
| `format`          | `article`, `documentation`, `video`, `talk`, `tool`, `course`, `book`, `repository` 같은 통제 값 |
| `areas`           | 하나 이상의 안정적인 분야 식별자                                                                 |
| `collections`     | 선택적 컬렉션 식별자                                                                             |
| `source_language` | 외부 자료의 언어                                                                                 |
| `published`       | 확인 가능하고 의미 있는 경우 원 게시 날짜                                                        |
| `added`           | 프로젝트가 참고 자료를 추가한 날짜                                                               |
| `reviewed`        | 최근 실질적 편집 검토 날짜                                                                       |
| `status`          | `draft`, `review`, `published`, `archived` 중 하나                                               |
| `preview`         | 선택적 승인 이미지 레코드와 출처 정보                                                            |
| `language`        | 프로젝트 소유 메타데이터의 언어                                                                  |
| `translation_of`  | 번역된 메타데이터가 참조하는 기준 참고 자료 식별자                                               |

구현 계획에서 필드 이름이나 저장 형식을 다듬을 수 있지만 이러한 책임은 유지해야 합니다.

## 선정 기준

다음 조건을 충족하는 자료는 좋은 후보입니다.

- 디자인 의도를 구현, 시스템, 인터랙션, 접근성, 도구 또는 프런트엔드 품질과 직접 연결한다.
- 지속 가능한 통찰, 유용한 예시 또는 권위 있는 지침을 포함한다.
- 식별 가능한 게시자나 저자와 안정적인 기준 목적지가 있다.
- 더 강한 기존 참고 자료를 중복하지 않고 의미 있는 범위를 추가한다.
- 실질적인 콘텐츠를 복제하지 않고 정확하게 요약할 수 있다.
- 대상 독자가 사용할 수 있거나 고급 자료임을 명확히 표시할 수 있다.

주로 홍보 목적이거나, 오해를 부르거나, 출처가 없거나, 정당한 이유 없이 접근하기 어렵거나, 검색 결과 요약보다 추가 가치가 없는 자료는 제외합니다.

## 출처 및 표시 정책

- 가능한 가장 직접적인 기준 출처로 연결합니다.
- 확인 가능한 경우 게시자와 저자를 표시합니다.
- 독창적인 요약을 작성하며 초록, 설명, 자막 또는 상당한 분량의 글을 복사하지 않습니다.
- 필요한 경우에만 짧게 인용하고 직접 출처를 표시합니다.
- 검색 결과 요약, 재게시물 또는 AI 생성 텍스트를 근거로 취급하지 않습니다.
- 확립된 제품, API, 기술 이름을 보존합니다.
- 출처의 소유권이 바뀌거나, 리디렉션되거나, 사라지면 갱신 또는 보관 전에 검토 결과를 기록합니다.

## 미리보기 이미지 정책

미리보기 이미지가 편집 검토를 통과하지 않았다면 프로젝트 소유의 중립적 대체 이미지를 사용합니다. 임의의 Open Graph 이미지를 자동으로 핫링크하지 않습니다. 이미지 출처 정보와 대체 텍스트를 기록하며 이미지 누락이 제목, 게시자, 요약 또는 목적지 링크를 가리지 않게 합니다.

전체 외부 출처 결정은 [`docs/decisions/0002-reference-records-and-external-sources.md`](../decisions/0002-reference-records-and-external-sources.md)에 기록되어 있습니다.

## 편집 문체

- 디자인 엔지니어링의 한 분야만 알고 있을 수 있는 지적인 독자를 위해 간결하고 사실에 기반한 요약을 작성합니다.
- “필독”, “최고”, “업계 표준” 같은 홍보성 표현 대신 구체적인 가치를 설명합니다.
- 출처가 주장하는 내용과 프로젝트의 편집 판단을 구분합니다.
- 폭넓은 칭찬보다 구체적인 설명을 우선합니다.
- 한국어 번역에 안정적인 원문이 되도록 영문 용어를 일관되게 사용합니다.

## 영어 및 한국어 워크플로

첫 릴리스에서 프로젝트 소유 메타데이터의 기준 언어로 영어를 사용합니다. 외부 자료는 명시적으로 기록한 어떤 원문 언어로도 제공될 수 있습니다.

한국어 번역은 영문 참고 자료 레코드의 상태가 `published`가 된 후 시작합니다. 각 번역은 다음 기준을 따릅니다.

- `translation_of`를 통해 기준 영문 레코드를 참조합니다.
- 검토된 한국어판이 없는 한 같은 외부 목적지를 가리킵니다.
- 번역이 모호함을 만들 수 있는 코드, API 이름, 출판물 이름, 확립된 영문 용어는 원문을 유지합니다.
- 프로젝트 소유 요약과 관련성 설명의 주장을 바꾸지 않고 번역합니다.
- 기준 영문 메타데이터가 실질적으로 변경되면 번역본도 다시 검토합니다.

첫 공개 버전이 영문 메타데이터만 제공하더라도 편집자는 번역의 최신 상태를 확인할 수 있어야 합니다.

## 편집 워크플로

1. **제안** — 자료가 범위에 맞고 더 약한 중복 자료가 아닌지 확인합니다.
2. **평가** — 전체 출처, 게시자, 관련성, 지속성, 접근 조건을 확인합니다.
3. **기록** — [`templates/reference-record.md`](../../templates/reference-record.md)를 사용해 레코드를 만듭니다.
4. **검증** — 기준 URL, 출처 표시, 메타데이터, 요약 정확성, 미리보기 출처를 확인합니다.
5. **검토** — 선정 품질, 편집 명료성, 접근성, 분류, 링크를 평가합니다.
6. **게시** — 필수 검사를 통과한 후에만 상태를 변경합니다.
7. **유지관리** — 리디렉션, 실패, 오래된 메타데이터, 실질적인 출처 변경을 다시 확인합니다.
8. **보관 또는 대체** — 일반 탐색에서 부적합한 자료를 제거하면서 편집 이력을 보존합니다.

## 콘텐츠 품질 체크리스트

다음 조건을 충족하면 참고 자료를 게시할 수 있습니다.

- 제목, 목적지, 게시자, 저자 정보가 정확하다.
- 요약과 관련성 설명이 독창적이고 간결하며 출처에 충실하다.
- 형식, 분야, 컬렉션이 올바르다.
- 검색 결과 요약만으로 판단하지 않고 전체 출처를 확인했다.
- 목적지가 기준 URL이며 현재 접근 가능하거나 예외를 문서화했다.
- 미리보기 이미지 출처가 승인되었거나 중립적 대체 이미지를 사용한다.
- 링크 텍스트와 카드 콘텐츠를 맥락 없이도 이해할 수 있다.
- 번역된 메타데이터가 있다면 올바른 기준 레코드를 가리킨다.
- 임시 편집 메모가 남아 있지 않다.
- AI가 발견이나 초안 작성을 지원했더라도 사람이 최종 편집 검토를 책임진다.
