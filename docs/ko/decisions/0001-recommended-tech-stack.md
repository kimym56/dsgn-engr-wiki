## 맥락

DSGN ENGR Wiki는 인증 없이 읽을 수 있는 공개 디자인 엔지니어링 참고 자료 라이브러리입니다. 첫 버전에는 구조화된 로컬 자료 레코드, 접근 가능한 탐색, 강력한 정적 렌더링, 신뢰할 수 있는 검증, 유지관리 부담이 적은 배포 경로가 필요합니다.

저장소는 아직 개발 단계에 들어가지 않았습니다. 이 기록은 패키지를 설치하거나 버전을 고정하지 않고 방향을 제안합니다. 구현 계획을 승인할 때 안정 버전을 선택하고 기록해야 합니다.

## 권장 결정

다음을 사용합니다.

- 라우팅, 레이아웃, 메타데이터, 정적 렌더링, 향후 현지화 경계에 **Next.js App Router**
- UI와 콘텐츠 도구에 엄격한 TypeScript 설정을 적용한 **React**
- 주요 콘텐츠 소스로 **스키마 검증을 거친 로컬 자료 레코드**
- 편집 페이지, 컬렉션 소개 또는 인터랙티브 설명이 문서형 콘텐츠의 이점을 얻는 경우에만 **로컬 Markdown 또는 MDX 파일**
- 자료 메타데이터, 분야, 컬렉션, 관계, 로케일 메타데이터를 위한 **소규모 스키마 검증 계층**
- 시각 시스템에 **CSS 사용자 정의 속성과 프로젝트 소유 스타일**. 구현 계획에서 명확한 이점이 입증될 때만 스타일링 프레임워크를 도입합니다.
- 단위 및 컴포넌트 동작에 **Vitest와 Testing Library**
- 브라우저 여정 및 접근성 중심 인터랙션 검사에 **Playwright Test**
- 주변 포트폴리오 프로젝트와 일치하는 초기 패키지 관리자로 **npm**
- 초기 미리보기 및 프로덕션 배포 대상으로 **Vercel**

초기 아키텍처에는 데이터베이스, 인증, 헤드리스 CMS 또는 호스팅 검색 서비스가 필요하지 않아야 합니다.

## 근거

Next.js App Router는 파일 기반 라우팅, 메타데이터 생성, 정적 렌더링, 현재 React 서버 기능을 제공합니다. 공식 MDX 통합은 모든 외부 참고 자료를 MDX로 표현하지 않고도 제한된 저작 콘텐츠에 유용합니다.

로컬 자료 레코드는 큐레이션, 검토 이력, 구현 변경을 하나의 Git 워크플로 안에 유지합니다. 검증 계층은 배포 전에 메타데이터와 관계 오류를 찾을 수 있습니다. 참고 자료, 분야, 컬렉션 페이지를 정적으로 렌더링하고, 생성된 로컬 인덱스로 호스팅 서비스 없이 탐색과 가벼운 검색을 지원할 수 있습니다. Vitest는 빠르고 집중된 테스트 실행을 지원하고, Playwright는 실제 브라우저에서 사용자에게 보이는 동작을 검증합니다.

프로젝트 소유 CSS는 초기 디자인 시스템을 명시적으로 유지하고, 시각 요구사항을 알기 전에 추가적인 스타일 추상화에 얽매이지 않게 합니다.

## 검토한 대안

### 정적 사이트 생성기

Astro 또는 문서 중심 생성기는 클라이언트 측 JavaScript를 줄이고 강력한 콘텐츠 기본 요소를 제공할 수 있습니다. 구현 계획에서 제품이 거의 완전히 정적이며 React 중심 인터랙션 패턴이 필요하지 않다는 점이 드러나면 여전히 유효한 대안입니다.

### 처음부터 헤드리스 CMS 사용

CMS는 브라우저 기반 편집 인터페이스를 제공하지만, 편집 워크플로가 검증되기 전에 스키마 중복, 접근 제어, 미리보기 통합, 마이그레이션 작업, 서비스 소유권을 도입합니다.

### 데이터베이스 기반 맞춤 콘텐츠 시스템

맞춤 데이터베이스 모델은 계정, 개인화, 복잡한 쿼리를 지원할 수 있지만 이 중 어느 것도 초기 요구사항이 아닙니다. 첫 참고 자료 탐색 경험을 개선하지 않으면서 운영 및 테스트 부담을 늘립니다.

### 처음부터 스타일링 프레임워크 사용

유틸리티 또는 컴포넌트 프레임워크는 일반적인 레이아웃 작업을 빠르게 할 수 있습니다. 그러나 제품의 주제상 투명한 디자인 시스템 결정이 특히 중요하므로, 시각적 방향과 컴포넌트 요구를 이해한 후에만 선택해야 합니다.

## 결과

- 초기 콘텐츠 변경에는 브라우저 CMS 대신 Git 검토를 사용합니다.
- 자료 스키마, 관계 검증기, 생성된 탐색 인덱스는 프로젝트가 소유하는 중요한 코드가 됩니다.
- 참고 자료, 분야, 컬렉션 페이지는 정적으로 렌더링해야 합니다. 클라이언트 측 JavaScript는 필터링과 언어 컨트롤처럼 필요한 인터랙션으로 제한해야 합니다.
- 편집 콘텐츠의 이식성과 검토 가능성을 유지하도록 MDX 컴포넌트를 의도적으로 제한해야 합니다.
- 한국어 게시가 나중에 시작되더라도 기반 단계에서 로케일 대응 경로를 구축해야 합니다.
- 검색은 생성된 인덱스나 가벼운 로컬 방식으로 시작할 수 있으며, 근거 없이 서비스 의존성으로 전환해서는 안 됩니다.
- 외부 자료 레코드와 미리보기 자산은 [결정 0002](0002-reference-records-and-external-sources.md)를 따릅니다.
- 애플리케이션 개발을 시작하기 전까지는 프레임워크를 비교적 적은 비용으로 재검토할 수 있습니다.

## 승인 전 검증

첫 구현 계획은 권장 스택이 다음을 수행할 수 있는지 확인해야 합니다.

1. 로컬 레코드에서 샘플 참고 자료, 분야, 컬렉션 페이지를 렌더링한다.
2. 개발 및 지속적 통합 중에 자료 메타데이터와 레코드 간 관계를 검증한다.
3. 호스팅 검색 서비스 없이 로컬 탐색 또는 검색 인덱스를 생성한다.
4. 누락된 번역을 게시하지 않으면서 로케일 대응 경로를 생성한다.
5. 최소한의 클라이언트 측 JavaScript로 접근성 및 성능 기대치를 충족한다.
6. 영구 인프라를 추가하지 않고 미리보기 빌드를 배포한다.

짧은 기술 검증 작업에서 이 중 하나라도 불가능한 것으로 확인되면 전체 제품을 스캐폴딩하기 전에 이 기록을 수정하거나 대체합니다.
