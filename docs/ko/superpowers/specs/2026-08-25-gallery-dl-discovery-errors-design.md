# Gallery-dl 탐색 오류 보고

> [!IMPORTANT]
> 이 문서는 [영문 원본](../../../superpowers/specs/2026-08-25-gallery-dl-discovery-errors-design.md)의 한국어 검토 번역입니다. 영문 버전이 권위 있는 원본입니다.

## 문제

`gallery-dl --dump-json`은 내장된 type-`-1` 오류 메시지를 반환하면서도 성공적으로 종료될 수 있습니다. 현재 Designparser 탐색 어댑터는 type `3`을 제외한 모든 메시지를 무시하므로, 네트워크 장애가 “gallery-dl 탐색에서 릴스를 찾지 못했습니다.”라고 잘못 보고됩니다. 이로 인해 운영상의 원인이 감춰지고 게시물이 있는 Instagram 프로필이 비어 있는 것처럼 보입니다.

## 결정

릴스 다운로드를 수집하기 전에 파싱된 탐색 메시지에 내장된 gallery-dl 오류가 있는지 검증합니다. 오류 메시지가 존재하면 해당 오류의 이름과 메시지에서 도출한 간결한 원인과 함께 탐색을 실패 처리합니다. 기존의 0이 아닌 종료, 중단, 잘못된 형식의 출력, 실제로 결과가 비어 있는 경우의 동작은 그대로 유지합니다.

네트워크 접근은 계속 실행 환경의 권한으로 남습니다. 저장소에는 재시도, 대체 스크레이퍼, 또는 샌드박스 우회를 시도하는 코드를 추가하지 않습니다.

## 데이터 흐름

1. 기존 프로필 URL, Chrome 쿠키, 릴스 전용 옵션으로 `gallery-dl`을 실행합니다.
2. 프로세스 종료 상태를 검증하고 JSON 출력을 파싱합니다.
3. 내장된 type-`-1` 오류 메시지를 감지하고 보고된 원인과 함께 중단합니다.
4. 기존 필터와 정렬을 사용해 유효한 type-`3` 릴스 메시지를 정규화합니다.
5. 파싱된 응답에 내장 오류도 유효한 릴스도 없을 때만 “릴스를 찾지 못했습니다.”라고 보고합니다.

## 오류 처리

내장 메시지가 gallery-dl type-`-1` 형태이며 객체 페이로드를 가진 경우에만 오류로 처리합니다. 문자열 `error` 및 `message` 필드에서 길이가 제한되고 민감하지 않은 진단 메시지를 생성합니다. 해당 필드가 없으면 일반적인 내장 오류 메시지를 대신 사용합니다. 미디어 URL이나 쿠키 데이터는 포함하지 않습니다.

## 검증

- type-`-1` DNS 장애가 “릴스를 찾지 못했습니다.” 대신 실제 원인을 보고함을 입증하는 집중적인 어댑터 테스트를 추가합니다.
- 실제로 탐색 결과가 비어 있는 동작을 보호하기 위해 기존 빈 배열 테스트를 유지합니다.
- Designparser 명령 어댑터 테스트를 실행합니다.
- 네트워크 권한으로 전체 다이제스트 준비 및 완료 워크플로를 실행합니다.
