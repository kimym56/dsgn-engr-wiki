# 개발 프로세스

> 이 문서는 [`docs/development-process.md`](../development-process.md)의 한국어 번역본입니다. 영문 원본을 기준 문서로 사용합니다.

## 현재 경계

현재 저장소에는 문서만 있습니다. 첫 개발 작업은 승인된 구현 계획을 기반으로 해야 합니다. 승인 전에는 애플리케이션 스캐폴드, 의존성, 런타임 설정 또는 프로덕션 참고 자료 레코드를 추가하지 않습니다.

## 제공 원칙

1. 문서화된 방문자 또는 편집 결과에 연결된 작고 검토 가능한 단위로 작업합니다.
2. 자료 데이터, 표현 계층, 검증, 유지관리 도구를 각각 독립적으로 이해할 수 있게 유지합니다.
3. 검토된 로컬 데이터에서 공개 페이지를 결정론적으로 렌더링합니다.
4. 구현 세부 사항뿐 아니라 사용자에게 보이는 동작과 자료 무결성을 테스트합니다.
5. 접근성, 반응형 동작, 성능을 인수 기준으로 다룹니다.
6. 향후 작업을 제약하는 결정은 `docs/decisions/`에 기록합니다.
7. 문서화된 요구가 필요로 하기 전에는 서비스, 데이터베이스, 런타임 스크레이핑 또는 추상화를 도입하지 않습니다.

## 계획된 제공 단계

### 단계 0 — 준비

제품, 참고 자료 모델, 정보 구조, 권장 기술 스택, 외부 출처 정책, 프로세스, 로드맵을 정의합니다. 현재 이 저장소는 이 단계에 있습니다.

### 단계 1 — 기반

구현 계획에 정의된 최소 애플리케이션 스캐폴드, 품질 도구, 로케일 대응 라우팅, 디자인 기반, 지속적 검증을 구축합니다.

### 단계 2 — 참고 자료 시스템

자료, 분야, 컬렉션 스키마와 검증, 로컬 인덱스 생성, 작성 템플릿, 중립적 미리보기 대체 이미지, 검토된 소규모 샘플 세트를 구현합니다.

### 단계 3 — 핵심 발견 경험

홈, 참고 자료, 탐색, 분야, 컬렉션, 소개 페이지를 구현합니다. 샘플 라이브러리에 필요한 필터링을 추가합니다. 탐색과 필터링이 충분하지 않다는 사실이 테스트에서 확인될 때만 검색을 추가합니다.

### 단계 4 — 릴리스 품질

접근성 검토, 브라우저 간 검증, 성능 검사, 출처 및 표시 검토, 링크 상태 워크플로, 프로덕션 배포, 유지관리 문서를 완료합니다.

## 작업 항목 생명주기

1. 방문자 또는 편집 결과와 인수 기준을 정의합니다.
2. 영향을 받는 레코드, 경로, 컴포넌트, 검증 규칙, 인덱스, 테스트를 식별합니다.
3. 변경이 지속적인 제약을 만들면 결정을 기록합니다.
4. 작업 범위가 명확한 브랜치에서 가장 작은 완결된 단위를 구현합니다.
5. 개발 중에는 대상 검사를 실행하고 검토 전에는 전체 품질 검사를 실행합니다.
6. 사용자에게 보이는 동작, 접근성, 자료 무결성, 출처 표시, 문서를 검토합니다.
7. 검사를 통과하고 후속 작업을 명시적으로 분리한 경우에만 병합합니다.

## 계획된 품질 검사

애플리케이션 스캐폴드는 다음 명령을 제공해야 합니다.

- 포매팅 또는 포매팅 검증
- 린트
- TypeScript 검사
- 자료 스키마 및 내부 관계 검증
- 로컬 탐색 또는 검색 인덱스 생성
- 단위 및 컴포넌트 테스트
- 브라우저 기반 종단 간 및 접근성 검사
- 프로덕션 빌드

정확한 명령 이름은 구현 계획과 스캐폴드에서 정합니다. 정의한 후에는 저장소 루트에 문서화하고 지속적 통합에서 실행해야 합니다.

외부 링크 상태 검사는 유지관리의 일부지만 결정론적 프로덕션 빌드와 분리해야 합니다. 일시적인 제3자 장애가 유효한 로컬 레코드의 배포를 막아서는 안 됩니다.

## 테스트 기대사항

### 자료 검증

필수 메타데이터, 고유 식별자, URL 형식, 지원하는 자료 형식, 분야 식별자, 컬렉션 관계, 상태 값, 날짜, 로케일 관계, 번역 최신성 신호, 미리보기 이미지 레코드를 검증합니다.

### 단위 및 컴포넌트 테스트

레코드 파싱, 검증 오류, 필터링, 인덱스 생성, 관계 도우미, 로케일 선택, 외부 링크 표현, 미리보기 대체 화면을 다룹니다. 보호하려는 동작을 불분명하게 만드는 스냅숏 테스트는 피합니다.

### 브라우저 테스트

다음과 같은 주요 방문자 여정을 다룹니다.

- 홈으로 진입해 전체 참고 자료 색인을 탐색한다.
- 분야 또는 형식으로 참고 자료를 필터링하고 잘못된 필터에서 복구한다.
- 분야를 통해 참고 자료를 발견한다.
- 편집 컬렉션을 연다.
- 외부 목적지를 따라가기 전에 식별한다.
- 검토된 프로젝트 메타데이터가 있을 때 언어를 전환한다.
- 선택적 저자 또는 미리보기 이미지가 없는 자료를 탐색한다.
- 알 수 없거나 게시되지 않은 분야 또는 컬렉션에서 적절히 복구한다.

브라우저 테스트는 사용자에게 보이는 동작을 검증하고 서로 독립적으로 유지해야 합니다. 테스트가 외부 게시자의 접속 가능 여부에 의존해서는 안 됩니다.

### 링크 상태 검사

별도의 유지관리 검사는 리디렉션, 지속적 실패, 영향을 받는 레코드 식별자를 보고해야 합니다. 일시적 실패와 반복되는 실패를 구분하고 레코드를 자동으로 수정하거나 보관해서는 안 됩니다.

### 접근성 검토

자동화 검사는 키보드 검토, 포커스 순서 검토, 시맨틱 제목 구조 검토, 외부 링크 목적 검토, 확대 및 리플로 검사, 보조 기술 표본 검사를 지원하지만 이를 대체하지는 않습니다.

## 오류 처리 기대사항

- 유효하지 않은 로컬 레코드는 개발 및 지속적 통합에서 실행 가능한 오류 메시지와 함께 실패해야 합니다.
- 잘못된 분야, 컬렉션 또는 번역 관계는 배포 전에 실패해야 합니다.
- 잘못된 필터 값은 비어 있거나 깨진 페이지 대신 유용한 색인으로 복구해야 합니다.
- 알 수 없는 경로는 복구 내비게이션이 포함된 유용한 찾을 수 없음 페이지를 제공해야 합니다.
- 선택적 메타데이터 또는 미리보기가 없어도 그 외에는 유효한 참고 자료가 중단되어서는 안 됩니다.
- 번역이 없을 때는 빈 로케일 페이지를 노출하지 않고 기준 언어를 계속 제공해야 합니다.
- 외부 출처 장애가 정적 페이지 렌더링을 막아서는 안 됩니다.

## 개발 작업 단위의 완료 정의

다음 조건을 충족하면 변경이 완료된 것입니다.

- 인수 기준을 충족한다.
- 관련 자동화 검사를 통과한다.
- 영향을 받는 방문자 및 편집 여정을 적절한 뷰포트 크기에서 수동으로 검사했다.
- 키보드 및 시맨틱 접근성을 검토했다.
- 로컬 레코드, 내부 관계, 출처 표시, 미리보기 출처 정보가 유효하다.
- 빌드 성공이 출처 접속 가능 여부에 의존하지 않으면서 외부 링크 동작을 확인했다.
- 문서와 결정 기록에 지속적인 변경사항이 반영되어 있다.
- 비밀 정보, 임시 디버그 동작 또는 설명되지 않은 경고가 남아 있지 않다.

## 의사결정 프로세스

다음과 같은 선택을 할 때 아키텍처 결정 기록을 작성합니다.

- 되돌리기 어렵다.
- 서비스 또는 중요한 의존성을 도입한다.
- 자료 스키마, 공개 URL 구조 또는 외부 출처 정책을 변경한다.
- 개인정보 보호, 접근성, 현지화, 저작권 위험 또는 배포에 영향을 준다.
- 향후 기여자가 따라야 하는 규칙을 만든다.

[`templates/decision-record.md`](../../templates/decision-record.md)를 사용하고 승인된 결정은 [`docs/decisions/README.md`](../decisions/README.md)의 색인에 추가합니다.
