# Source analysis: App Dissection

## Editorial evaluation

### Scope fit

Brian Lovin's directory collects 22 app dissections covering interaction, visual detail, flows, and product decisions in well-known mobile products. The practice of closely observing shipped interfaces is relevant to developing taste. The directory page itself is an index, not the substantive analysis, and all displayed entry dates fall between February and May 2016.

### Authority and durability

The openly accessible page is a first-party directory for the author's own dissections. It is valuable as practitioner observation, not controlled UX research. Product screenshots and conclusions may be historically useful but technically stale.

### Overlap and classification

Proposed format: `directory`. Proposed Areas: `interface-analysis`, `product-craft`. It operationalizes the observation practice suggested by `developing-taste`, while `devouring-details` offers a newer collection of interface details.

### Editorial recommendation

`review` as a historical practice archive. The page is a strong discovery node, but individual dissections should be evaluated before any product lesson is adopted.

## Website design analysis

### Information hierarchy and navigation

A concise title and chronological grid/list of named app entries make the collection immediately browsable. Minimal framing shifts interpretation work to the linked dissections.

### UI, interaction, and motion

The directory exposes card-like entry links and standard site navigation. Child pages and hover/focus/motion states were deliberately not opened or exercised in this wave.

### Grid, layout, and responsive behavior

Repeated entries create a regular catalog structure suitable for scanning. Actual column changes and mobile reflow were not visually tested.

### Typography, color, and visual rhythm

App names and repeated preview treatment create rhythm through consistency rather than deep hierarchy. Exact visual styling, image treatment, and contrast were not audited.

### Accessibility observations

Descriptive app-name links are preferable to generic labels, but focus visibility, image alternatives, target size, and responsive reading order remain unverified.

### Transferable principles

- Learn taste by documenting specific interface behavior, not collecting inspiration alone.
- Keep a directory lightweight and let each entry carry the detailed argument.
- Date interface observations so readers can interpret old conventions.
- Separate observation from adoption; test extracted principles in the current product.

### Source-specific expression to avoid copying

Do not reuse screenshots, app branding, card imagery, prose, catalog styling, or specific dissections as this project's visual identity.

- Historical age is an editorial caution, not a conclusion that every underlying principle is obsolete.
