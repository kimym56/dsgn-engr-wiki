# 공개 참고자료 기반 설계

## 목적

공개 참고자료 워크플로 대상으로 이미 승인된 DENG 웨이브 1 후보 9개를 스키마로 검증하는 최초의 로컬 참고자료 세트로 전환하고, 승인된 레코드를 영문 References 색인에 공개한다.

이 작업은 실제 편집 콘텐츠로 공개 레코드 모델을 입증한다. 탐색 그래프를 확장하거나, 한국어 메타데이터를 게시하거나, 외부 콘텐츠를 복사하거나, 로컬 참고자료 상세 페이지를 추가하지 않는다.

## 승인된 릴리스 범위

- 프로젝트가 소유한 영문 메타데이터만 게시한다.
- 한국어 출처 분석 번역은 내부 검토 보조 자료로 유지한다.
- `/ko`는 게시하지 않은 상태로 유지한다.
- 정확히 다음 9개의 승인된 후보에 대한 레코드를 만든다.
  - `taste-is-eating-silicon-valley`
  - `web-interface-guidelines`
  - `developing-taste`
  - `pasito`
  - `vaul`
  - `family-wallet`
  - `on-taste-part-3`
  - `manage-design-projects`
  - `ux-engineer-a-terminal-career`
- 공개 카드는 각각의 기준 외부 출처로 같은 브라우저 탭에서 직접 연결한다.
- 로컬 참고자료 상세 페이지는 미룬다.
- 웨이브 3 후보는 검사하거나 분석하지 않는다.
- 요청 처리 또는 프로덕션 빌드 중에 외부 출처를 가져오지 않는다.

## 저장소 아키텍처

### 참고자료 레코드

영문 참고자료마다 JSON 문서 하나를 저장한다.

```text
content/references/en/<reference-id>.json
```

각 문서는 애플리케이션 코드가 아니라 편집 데이터이다. 레코드 스키마는 다음을 포함한다.

| 필드              | 요구사항                                                   |
| ----------------- | ---------------------------------------------------------- |
| `id`              | 필수인 안정적인 소문자 kebab-case 식별자                   |
| `title`           | 필수인 검증된 자료 제목                                    |
| `url`             | 필수인 기준 절대 HTTPS URL                                 |
| `publisher`       | 필수인 출처 조직 또는 발행처                               |
| `author`          | 선택적인 저자 문자열 또는 `null`                           |
| `summary`         | 필수인 간결하고 독창적인 출처 설명                         |
| `relevance`       | 필수인 디자인 엔지니어링 가치에 대한 독창적인 설명         |
| `format`          | 필수인 통제된 형식 식별자                                  |
| `areas`           | 필수인 유효한 Area 식별자의 비어 있지 않은 목록            |
| `collections`     | 필수인 유효한 Collection 식별자 목록. 처음에는 비어 있음   |
| `source_language` | 필수인 출처 언어 코드. 이 세트에서는 `en`                  |
| `published`       | 선택적인 원래 게시일 또는 `null`                           |
| `added`           | 필수인 공개 레코드가 이 워크플로에 들어온 날짜             |
| `reviewed`        | 필수인 가장 최근의 실질적인 편집 검토일                    |
| `status`          | 필수인 `draft`, `review`, `published` 또는 `archived` 상태 |
| `preview`         | 선택적인 승인된 미리보기 객체 또는 `null`. 처음에는 `null` |
| `language`        | 필수인 프로젝트 메타데이터 로케일. 이 릴리스에서는 `en`    |
| `translation_of`  | 기준 영문 레코드에서는 `null`                              |

초기 통제 형식은 `article`, `documentation`, `tool`, `case-study`이며, 추측에 의한 형식을 만들지 않고 승인된 자료 9개를 모두 포괄한다.

### Area 레지스트리

영문 Area 레지스트리를 다음 위치에 저장한다.

```text
content/areas/en.json
```

제품 브리프에서 이미 승인한 8개 Area를 사용한다.

- `design-engineering-foundations`
- `interface-implementation`
- `interaction-and-motion`
- `design-systems-and-tokens`
- `prototyping-and-tooling`
- `accessibility-and-inclusive-design`
- `collaboration-handoff-and-workflow`
- `frontend-quality-and-performance`

각 Area에는 식별자, 영문 레이블, 간결한 설명이 있다. 레코드 작성 체크포인트에서는 분석에 제안된 더 세분화된 레이블을 이 안정적인 공개 레지스트리에 대응시키며, 새로운 Area를 암묵적으로 만들지 않는다.

### Collection 레지스트리

처음에는 비어 있는 영문 Collection 레지스트리를 다음 위치에 저장한다.

```text
content/collections/en.json
```

빈 레지스트리는 편집 목적과 순서가 승인되기 전에 컬렉션을 만들어 내지 않으면서도 관계 검증을 입증한다.

## 검증 및 로딩

서버 전용 콘텐츠 모듈이 로컬 JSON 파일을 읽고 검증된 타입 지정 레코드를 반환한다. 검증은 레코드를 렌더링하기 전에 실행되며, 실패할 때마다 정확한 파일과 필드를 보고한다.

검증은 다음을 거부한다.

- 누락되거나 알려지지 않은 필드
- 잘못된 형식의 ID, 언어 코드, URL 또는 ISO 날짜
- 중복된 ID 또는 기준 URL
- 지원하지 않는 형식 또는 상태
- 빈 Area 목록
- 레코드 안에서 중복된 Area 또는 Collection 관계
- 알려지지 않은 Area 또는 Collection 식별자
- 메타데이터 언어가 `en`이 아니거나 `translation_of`가 null이 아닌 영문 레코드
- 필수 출처 추적 정보와 대체 텍스트가 없는 미리보기 데이터

선택적인 `author`, `published`, `preview` 값에는 `null`을 사용할 수 있다. 빈 Collections는 유효하다. Archived 및 review 레코드는 유효한 편집 데이터로 유지하지만 공개 색인에서는 제외한다.

로더는 네트워크 요청을 수행하지 않는다. 개별 출처의 상태는 로컬 레코드의 렌더링 가능 여부를 절대로 결정하지 않는다.

## 공개 References 경험

### 페이지 구조

`/en/references`는 다음 요소가 있는 서버 렌더링 색인이 된다.

1. 기존 페이지의 아이브로, 제목 및 수정된 설명
2. 조건에 맞는 게시된 참고자료 수
3. Area 및 Format 필터
4. 반응형 참고자료 카드 목록 또는 그리드
5. 유효한 필터 조합에 일치하는 항목이 없을 때 유용한 결과 없음 상태

기존의 “first reviewed reference set is being prepared” 빈 상태는 제거한다.

편집 검사를 위해 개발 환경 전용 `?preview=review` 매개변수는 `review` 레코드를 포함하고 명확한 미리보기 배너를 표시한다. 프로덕션에서는 이 매개변수를 무시하므로 복사된 URL을 통해 게시되지 않은 메타데이터가 노출될 수 없다.

### 필터링

필터는 공유 가능한 쿼리 매개변수를 사용한다.

```text
/en/references?area=interaction-and-motion&format=article
```

필터링은 검증된 레코드를 바탕으로 서버에서 계산한다. 클라이언트 컴포넌트나 브라우저 저장소는 필요하지 않다. 알려지지 않은 Area 또는 Format 값은 승인된 정보 아키텍처에 맞게 전체 색인으로 폴백한다. 명확한 작업으로 `/en/references`를 복원한다.

### 카드

모든 카드는 방문자가 외부로 이동하기 전에 판단할 수 있도록 프로젝트 소유의 충분한 맥락을 보여 준다.

- 프로젝트가 소유한 중립적인 형식 표현
- 형식 레이블
- 제목
- 발행처 및 선택적인 저자
- 요약
- 관련성 메모
- Area 레이블
- 출처 언어
- 실질적인 검토일
- 명확하게 표현된 외부 출처 링크

카드는 출처 아트워크나 임의의 Open Graph 이미지를 사용하지 않는다. 외부 링크는 기준 URL을 사용하고, 아이콘 없이도 이해할 수 있으며, 현재 탭에서 열린다. 카드 전체를 하나의 지나치게 큰 링크로 만들지 않는다. 제목과 명시적인 행동 유도 문구가 명확한 링크 대상을 제공한다.

### Explore 문구

Explore는 이 구현 범위 밖에 둔다. 임시 문구는 이제 게시된 References 색인으로 방문자를 정확하게 안내하는 데 필요한 만큼만 변경한다. Area 및 Collection 페이지는 계속 미룬다.

## 편집 워크플로 및 사람의 승인 관문

1. 검증된 후보 파일과 영문 출처 분석 파일에서 JSON 레코드 9개를 작성한다.
2. 새 레코드를 모두 `review`로 설정한다.
3. 레코드를 검증하고 개발 환경 전용 검토 미리보기로 렌더링하여 편집 검사를 수행한다.
4. 9개 항목 모두의 제목, 출처 표시, 요약, 관련성 메모, 형식, Area, 날짜를 관리자에게 제시한다.
5. 요청된 수정을 적용한다.
6. 관리자가 명시적으로 승인한 후에만 9개 레코드의 상태를 `published`로 변경한다.
7. 후보, 색인 및 로그 레코드를 갱신하여 공개 참고자료 워크플로의 완료를 기록한다.

후보 수준의 `publication.decision: publish`는 이 워크플로 진입을 승인한 것이며, 새로 작성한 공개 메타데이터의 검토를 대신하지 않는다.

## 링크 상태

검증된 기준 URL을 읽고 다음을 보고하는 수동 유지보수 명령을 추가한다.

- 정상 목적지
- 리디렉션 및 확인된 목적지
- 이용할 수 없거나 시간 초과된 목적지

명령은 제한된 시간 초과를 사용하고 레코드별로 실행 가능한 결과를 출력한다. 페이지 렌더링, `next build` 또는 기본 저장소 품질 관문에서는 절대로 호출하지 않는다. 따라서 외부 장애가 공개 애플리케이션을 중단시킬 수 없다.

## 오류 처리

- 유효하지 않은 로컬 콘텐츠는 렌더링 전에 파일 및 필드 맥락과 함께 검증에 실패한다.
- 유효하지 않은 필터 값은 게시된 전체 색인으로 폴백한다.
- 일치 항목이 없는 유효한 필터는 결과 없음 설명과 명확한 작업을 보여 준다.
- 선택적인 출처 표시 또는 게시일이 없을 때 빈 시각적 자리표시자를 남기지 않는다.
- 미리보기가 없으면 항상 프로젝트의 중립적인 폴백을 렌더링한다.
- Review 및 archived 레코드는 공개 목록에 절대로 노출하지 않는다.
- 외부 상태 실패는 유지보수 발견 사항으로 남으며 레코드를 자동으로 변경하지 않는다.

## 테스트 전략

구현은 테스트 주도 개발을 따른다.

### 레코드 검증 테스트

- 완전하고 유효한 레코드를 허용한다.
- `null`인 선택 필드와 빈 Collections 목록을 허용한다.
- 잘못된 형식의 ID, URL, 언어 코드, 날짜를 거부한다.
- 누락되거나 알려지지 않은 필드를 거부한다.
- 중복된 ID와 기준 URL을 거부한다.
- 지원하지 않는 형식과 상태를 거부한다.
- 비어 있거나 알려지지 않은 Area 관계를 거부한다.
- 알려지지 않은 Collection 관계를 거부한다.
- 유효하지 않은 로케일과 번역 관계를 거부한다.
- 불완전한 미리보기 출처 추적 정보를 거부한다.

### 로딩 및 필터링 테스트

- 공개 색인에 대해 `published` 레코드만 반환한다.
- 결정론적인 편집 순서를 유지한다.
- Area, Format 및 둘의 교집합으로 필터링한다.
- 알려지지 않은 필터에는 모든 레코드로 폴백한다.
- 일치 항목이 없는 유효한 조합에는 빈 결과를 반환한다.

### 페이지 및 컴포넌트 테스트

- 기존 빈 상태를 게시된 항목 수와 카드로 대체한다.
- 제목, 출처 표시, 요약, 관련성, 메타데이터 및 Area 레이블을 제시한다.
- 설명적인 외부 링크 문구로 기준 출처에 연결한다.
- 선택적인 저자 및 게시일 UI를 깔끔하게 생략한다.
- 중립적인 미리보기 표현을 렌더링한다.
- 필터 레이블과 명확한 작업을 접근성 있게 제공한다.
- 유용한 유효 조건 결과 없음 상태를 제시한다.

### 브라우저 및 품질 검증

- 필터와 카드 링크 전반의 키보드 탐색 및 표시되는 포커스
- 모바일 및 데스크톱 너비의 반응형 레이아웃
- References 페이지의 자동 접근성 검사
- 프로덕션 빌드가 외부 콘텐츠 가져오기를 수행하지 않는다는 확인
- 레코드 검증, 포맷팅, 린팅, 타입 검사, 단위 테스트, 브라우저 테스트 및 프로덕션 빌드 통과

저장소 전체 품질 명령이 통과할 수 있도록 이전 계획 문서에 이미 존재하는 포맷팅 전용 경고 3개를 의미 변경 없이 정규화한다.

## 성능 및 구현 제약

- 페이지와 카드를 React Server Components로 유지한다.
- 필터 상태 또는 참고자료 데이터를 클라이언트 측 번들로 전송하지 않는다.
- 카드마다 한 번씩 읽고 검증하는 대신 서버 또는 빌드 실행마다 로컬 데이터를 한 번 읽고 검증한다.
- 구현 계획에서 표준 라이브러리와 기존 도구 체인이 불충분하다는 점을 입증하지 않는 한 새로운 런타임 의존성을 피한다.
- 검색, 페이지네이션, 애니메이션 시스템, CMS, 데이터베이스, 계정, 저장 상태 또는 개인화를 추가하지 않는다.

## 완료 기준

다음 조건을 충족하면 기능이 완료된다.

- 승인된 레코드 9개 모두 명시적인 메타데이터 검토 관문을 통과하고 `published`를 사용한다.
- 모든 레코드가 로컬 레지스트리를 기준으로 검증된다.
- `/en/references`가 네트워크 접근 없이 레코드 9개를 렌더링하고 필터링한다.
- 모든 카드가 출처의 정체성을 보존하고 기준 발행처에 연결한다.
- Review 또는 archived 레코드가 공개 색인에 나타나지 않는다.
- 검토 미리보기는 개발 환경에서만 작동하며 프로덕션에서 review 레코드를 노출할 수 없다.
- 누락된 선택 필드와 미리보기는 자연스럽게 폴백한다.
- 애플리케이션 작업을 차단하지 않고 링크 상태를 독립적으로 확인할 수 있다.
- 참고자료 색인과 활동 로그에 게시된 레코드가 반영된다.
- 저장소 전체 품질 관문을 통과한다.
